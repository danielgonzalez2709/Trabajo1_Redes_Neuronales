  archivo existe y su valor difiere del de defecto. Si un marcado coincide con un punto de la rejilla (tolerancia
  relativa 1e-9) no se duplica: ese punto lleva la marca. Lista ordenada de menor a mayor.
- El GD de paso fijo guarda un frame por iterado (`result["frames"]`: [{iter, positions: [[x, y]], best}]). Guarda la
  trayectoria SUBMUESTREADA: como máximo `PUNTOS_MAX` (constante con nombre, p. ej. 150) índices espaciados
  geométricamente, siempre con el primero (x0) y el último.

## Contrato del JSON (el otro implementador depende de esto; no lo cambies)
{
  "meta": {"func": "rosenbrock", "dim": 2, "method": "gdfijo", "seed": <base_seed + 0>, "k": <float>,
           "budget": <float>, "x0": [x, y], "puntos_max": <int>},
  "etas": [
    {"eta": <float>, "marca": null | "defecto" | "afinado", "f_best": <float>, "n_grad": <int>,
     "n_iter": <int, índice del último frame>, "iteraciones": [<int>, ...], "puntos": [[x, y], ...]}
  ]
}
`iteraciones` y `puntos` tienen la misma longitud; iteraciones[0] == 0, iteraciones[-1] == n_iter; puntos[0] == x0.

## Pruebas mínimas (escríbelas antes)

- La entrada marcada `defecto` reproduce `ejecutar_corrida` con la config sin tocar (mismo f_best, n_grad y último
  punto); con el archivo real, si existe la corrida versionada, coincide con su f_best (si no existe: skip).
- Rejilla: extremos incluidos, 4 por década, sin duplicados, orden ascendente, exactamente una marca `defecto`;
  `afinado` presente solo cuando se pasa una config afinada con otro valor.
- Submuestreo: longitudes, primer y último índice, índices estrictamente crecientes, a lo sumo PUNTOS_MAX.
- La config de entrada no se modifica. El JSON guardado se relee igual y no trae NaN/inf.
- Usa un presupuesto pequeño en las pruebas (rápidas); el archivo real se genera con base.yaml.
